# Проверка перед завершением

## Обзор

**Основной принцип:** доказательства перед утверждениями, всегда.

**Нарушить букву этого правила — значит нарушить его дух.**

## Железный закон

```
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

Если ты не запускал команду проверки в этом сообщении, ты не можешь утверждать, что она проходит.

## Функция контроля

```
BEFORE claiming any status or expressing satisfaction:

1. IDENTIFY: What command proves this claim?
2. RUN: Execute the FULL command (fresh, complete)
3. READ: Full output, check exit code, count failures
4. VERIFY: Does output confirm the claim?
   - If NO: State actual status with evidence
   - If YES: State claim WITH evidence
5. ONLY THEN: Make the claim

Skip any step = lying, not verifying
```

## Типичные ошибки

| Утверждение | Требуется | Недостаточно |
|-------------|-----------|--------------|
| Тесты проходят | Вывод команды тестов: 0 падений | Предыдущий запуск, «должно работать» |
| Линтер чист | Вывод линтера: 0 ошибок | Частичная проверка, экстраполяция |
| Сборка успешна | Команда сборки: код выхода 0 | Линтер прошёл, логи выглядят нормально |
| Ошибка исправлена | Проверка исходного симптома: проходит | Код изменён, предположили, что исправлено |
| Регрессионный тест работает | Цикл «красный–зелёный» подтверждён | Тест прошёл один раз |
| Агент завершил работу | Diff VCS показывает изменения | Агент сообщил об «успехе» |
| Требования выполнены | Пункт за пунктом по чек-листу | Тесты проходят |

## Красные флаги — СТОП

- Использование слов «должно», «наверное», «похоже»
- Выражение удовлетворения до проверки («Отлично!», «Идеально!», «Готово!» и т.п.)
- Собираешься делать коммит, push или PR без проверки
- Доверие отчётам агентов об успехе
- Опора на частичную проверку
- Мысль «только в этот раз»
- Устал и хочешь поскорее закончить
- **ЛЮБАЯ формулировка, подразумевающая успех без запуска проверки**

## Предотвращение рационализации

| Отговорка | Реальность |
|-----------|------------|
| «Теперь должно работать» | ЗАПУСТИ проверку |
| «Я уверен» | Уверенность ≠ доказательство |
| «Только в этот раз» | Исключений нет |
| «Линтер прошёл» | Линтер ≠ компилятор |
| «Агент сказал, что успешно» | Проверь самостоятельно |
| «Я устал» | Усталость ≠ оправдание |
| «Частичной проверки достаточно» | Частичная проверка ничего не доказывает |
| «Другие слова — правило не действует» | Дух важнее буквы |

## Ключевые паттерны

**Тесты:**
```
✅ [Run test command] [See: 34/34 pass] "All tests pass"
❌ "Should pass now" / "Looks correct"
```

**Регрессионные тесты (TDD, красный–зелёный):**
```
✅ Write → Run (pass) → Revert fix → Run (MUST FAIL) → Restore → Run (pass)
❌ "I've written a regression test" (without red-green verification)
```

**Сборка:**
```
✅ [Run build] [See: exit 0] "Build passes"
❌ "Linter passed" (linter doesn't check compilation)
```

**Требования:**
```
✅ Re-read plan → Create checklist → Verify each → Report gaps or completion
❌ "Tests pass, phase complete"
```

**Делегирование агентам:**
```
✅ Agent reports success → Check VCS diff → Verify changes → Report actual state
❌ Trust agent report
```

## Когда применять

**ВСЕГДА перед:**
- ЛЮБОЙ формулировкой об успехе или завершении
- ЛЮБЫМ выражением удовлетворения
- ЛЮБЫМ положительным утверждением о состоянии работы
- Коммитом, созданием PR, завершением задачи
- Переходом к следующей задаче
- Делегированием агентам

**Правило распространяется на:**
- Точные фразы
- Перефразирования и синонимы
- Подразумеваемый успех
- ЛЮБОЕ сообщение, которое намекает на завершённость или корректность
