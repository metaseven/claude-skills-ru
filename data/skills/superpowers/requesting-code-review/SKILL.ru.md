# Запрос код-ревью

Запусти субагента-ревьюера, чтобы поймать проблемы до того, как они начнут накапливаться. Ревьюер получает точно подготовленный контекст для оценки — но никогда не историю твоей сессии.

**Ключевой принцип:** проверяй рано, проверяй часто.

## Когда запрашивать ревью

**Обязательно:**
- После каждой задачи при разработке через субагентов
- После завершения крупной фичи
- Перед слиянием в main

**Необязательно, но полезно:**
- Когда застрял (свежий взгляд со стороны)
- Перед рефакторингом (проверка исходного состояния)
- После исправления сложного бага

## Как запросить

**1. Получи SHA коммитов:**
```bash
BASE_SHA=$(git rev-parse HEAD~1)  # or: git merge-base origin/main HEAD
HEAD_SHA=$(git rev-parse HEAD)
```

**2. Запусти субагента-ревьюера:**

Запусти субагента `general-purpose`, заполнив шаблон из [code-reviewer.md](code-reviewer.md)

**Плейсхолдеры:**
- `{DESCRIPTION}` - краткое описание того, что сделано
- `{PLAN_OR_REQUIREMENTS}` - что это должно делать
- `{BASE_SHA}` - начальный коммит
- `{HEAD_SHA}` - конечный коммит

**3. Работай с замечаниями:**
- Критичные проблемы исправь сразу
- Важные проблемы исправь до перехода дальше
- Мелкие проблемы отметь на потом
- Возражай, если ревьюер ошибается (с техническим обоснованием)

## Пример

```
[Just completed Task 2: Add verification function]

You: Let me request code review before proceeding.

BASE_SHA=$(git log --oneline | grep "Task 1" | head -1 | cut -d' ' -f1)
HEAD_SHA=$(git rev-parse HEAD)

[Dispatch code reviewer subagent]
  DESCRIPTION: Added verifyIndex() and repairIndex() with 4 issue types
  PLAN_OR_REQUIREMENTS: Task 2 from docs/superpowers/plans/deployment-plan.md
  BASE_SHA: a7981ec
  HEAD_SHA: 3df7661

[Subagent returns]:
  Strengths: Clean architecture, real tests
  Issues:
    Important: Missing progress indicators
    Minor: Magic number (100) for reporting interval
  Assessment: Ready to proceed

You: [Fix progress indicators]
[Continue to Task 3]
```

## Типичные отговорки

| Отговорка | Реальность |
|--------|---------|
| "Я просто сам просмотрю дифф вместо запуска ревьюера" | Ты координатор — построчный просмотр диффа съедает контекстное окно, которое нужно для ведения работы. Запусти субагента-ревьюера: дифф и оценка живут в его контексте, а тебе возвращаются только замечания. |
| "Ревьюеру нужна вся история моей сессии, чтобы понять изменение" | Передай ему точно подготовленный контекст, но никогда не историю сессии. Так ревьюер сосредоточен на результате работы, а не на ходе твоих мыслей. |

## Красные флаги

**НИКОГДА:**
- Не пропускай ревью со словами «это же просто»
- Не игнорируй критичные проблемы
- Не продолжай работу с неисправленными важными проблемами
- Не спорь с обоснованной технической критикой

**Если ревьюер ошибается:**
- Возрази с техническим обоснованием
- Покажи код или тесты, которые доказывают, что всё работает
- Запроси уточнение
