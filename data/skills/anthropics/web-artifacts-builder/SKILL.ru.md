# Web Artifacts Builder

Чтобы создать мощный фронтенд-артефакт claude.ai, выполни следующие шаги:
1. Инициализируй фронтенд-репозиторий с помощью `scripts/init-artifact.sh`
2. Разработай артефакт, редактируя сгенерированный код
3. Собери весь код в один HTML-файл с помощью `scripts/bundle-artifact.sh`
4. Покажи артефакт пользователю
5. (Необязательно) Протестируй артефакт

**Стек**: React 18 + TypeScript + Vite + Parcel (сборка) + Tailwind CSS + shadcn/ui

## Рекомендации по дизайну и стилю

ОЧЕНЬ ВАЖНО: чтобы избежать так называемого «AI slop» (шаблонного ИИ-мусора), не используй избыточно центрированные макеты, фиолетовые градиенты, одинаковые скругления углов и шрифт Inter.

## Быстрый старт

### Шаг 1: Инициализация проекта

Запусти скрипт инициализации, чтобы создать новый React-проект:
```bash
bash scripts/init-artifact.sh <project-name>
cd <project-name>
```

Это создаст полностью настроенный проект, в котором есть:
- ✅ React + TypeScript (через Vite)
- ✅ Tailwind CSS 3.4.1 с системой тем shadcn/ui
- ✅ Настроенные псевдонимы путей (`@/`)
- ✅ Более 40 предустановленных компонентов shadcn/ui
- ✅ Все зависимости Radix UI
- ✅ Parcel, настроенный для сборки (через .parcelrc)
- ✅ Совместимость с Node 18+ (автоопределение и фиксация версии Vite)

### Шаг 2: Разработка артефакта

Чтобы создать артефакт, редактируй сгенерированные файлы. Подробности см. в разделе **Common Development Tasks** ниже.

### Шаг 3: Сборка в один HTML-файл

Чтобы собрать React-приложение в один HTML-артефакт:
```bash
bash scripts/bundle-artifact.sh
```

Это создаст `bundle.html` — самодостаточный артефакт со всем JavaScript, CSS и зависимостями внутри файла. Этот файл можно сразу передать в диалог Claude как артефакт.

**Требования**: в корне проекта должен быть файл `index.html`.

**Что делает скрипт**:
- Устанавливает зависимости для сборки (parcel, @parcel/config-default, parcel-resolver-tspaths, html-inline)
- Создаёт конфиг `.parcelrc` с поддержкой псевдонимов путей
- Собирает проект с помощью Parcel (без source map)
- Встраивает все ресурсы в один HTML с помощью html-inline

### Шаг 4: Передача артефакта пользователю

Наконец, передай собранный HTML-файл в диалог, чтобы пользователь мог открыть его как артефакт.

### Шаг 5: Тестирование и визуальная проверка артефакта (необязательно)

Примечание: этот шаг полностью необязательный. Выполняй его только при необходимости или по запросу.

Чтобы протестировать или визуально проверить артефакт, используй доступные инструменты (в том числе другие скилы или встроенные инструменты, например Playwright или Puppeteer). Как правило, не тестируй артефакт заранее, так как это добавляет задержку между запросом и готовым результатом. Тестируй позже, уже после показа артефакта, если это запрошено или если возникли проблемы.
