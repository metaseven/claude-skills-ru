# Руководство по разработке MCP-сервера

## Обзор

Создавай MCP-серверы (Model Context Protocol), которые позволяют LLM взаимодействовать с внешними сервисами через продуманно спроектированные инструменты. Качество MCP-сервера измеряется тем, насколько хорошо он помогает LLM решать реальные задачи.

---

# Процесс

## 🚀 Общий порядок работы

Создание высококачественного MCP-сервера включает четыре основных этапа:

### Этап 1: Глубокое исследование и планирование

#### 1.1 Пойми современный дизайн MCP

**Покрытие API и инструменты-процессы:**
Балансируй между полным покрытием эндпоинтов API и специализированными инструментами-процессами. Инструменты-процессы удобнее для конкретных задач, а полное покрытие даёт агенту гибкость в комбинировании операций. Производительность зависит от клиента: одним клиентам полезно выполнение кода, которое комбинирует базовые инструменты, другим лучше работают инструменты более высокого уровня. Если сомневаешься, отдавай приоритет полному покрытию API.

**Именование инструментов и поиск:**
Понятные, описательные имена помогают агентам быстро находить нужные инструменты. Используй единые префиксы (например, `github_create_issue`, `github_list_repos`) и имена, начинающиеся с действия.

**Управление контекстом:**
Агентам полезны короткие описания инструментов и возможность фильтровать и постранично получать результаты. Проектируй инструменты так, чтобы они возвращали точечные, релевантные данные. Некоторые клиенты поддерживают выполнение кода, которое помогает агентам эффективно фильтровать и обрабатывать данные.

**Понятные сообщения об ошибках:**
Сообщения об ошибках должны подсказывать агенту решение: давать конкретные рекомендации и следующие шаги.

#### 1.2 Изучи документацию протокола MCP

**Навигация по спецификации MCP:**

Начни с карты сайта, чтобы найти нужные страницы: `https://modelcontextprotocol.io/sitemap.xml`

Затем загружай конкретные страницы с суффиксом `.md`, чтобы получить их в формате Markdown (например, `https://modelcontextprotocol.io/specification/draft.md`).

Ключевые страницы для изучения:
- Обзор спецификации и архитектура
- Транспортные механизмы (streamable HTTP, stdio)
- Определения инструментов, ресурсов и промптов

#### 1.3 Изучи документацию фреймворка

**Рекомендуемый стек:**
- **Язык**: TypeScript. У него качественная поддержка SDK и хорошая совместимость со средами выполнения, например MCPB. Кроме того, ИИ-модели хорошо пишут TypeScript-код: язык широко распространён, статически типизирован и хорошо поддерживается линтерами.
- **Транспорт**: Streamable HTTP для удалённых серверов с stateless JSON. Это проще масштабировать и поддерживать, чем stateful-сессии и потоковые ответы. Для локальных серверов используй stdio.

**Загрузи документацию фреймворка:**

- **Лучшие практики MCP**: [📋 Открыть лучшие практики](./reference/mcp_best_practices.md). Основные рекомендации

**Для TypeScript (рекомендуется):**
- **TypeScript SDK**: загрузи `https://raw.githubusercontent.com/modelcontextprotocol/typescript-sdk/main/README.md` через WebFetch
- [⚡ Руководство по TypeScript](./reference/node_mcp_server.md). Паттерны и примеры на TypeScript

**Для Python:**
- **Python SDK**: загрузи `https://raw.githubusercontent.com/modelcontextprotocol/python-sdk/main/README.md` через WebFetch
- [🐍 Руководство по Python](./reference/python_mcp_server.md). Паттерны и примеры на Python

#### 1.4 Спланируй реализацию

**Изучи API:**
Просмотри документацию API сервиса и определи ключевые эндпоинты, требования к аутентификации и модели данных. При необходимости используй веб-поиск и WebFetch.

**Выбор инструментов:**
Отдавай приоритет полному покрытию API. Составь список эндпоинтов для реализации, начиная с самых распространённых операций.

### Этап 2: Реализация

#### 2.1 Настрой структуру проекта

См. руководства для конкретного языка по настройке проекта:
- [⚡ Руководство по TypeScript](./reference/node_mcp_server.md). Структура проекта, package.json, tsconfig.json
- [🐍 Руководство по Python](./reference/python_mcp_server.md). Организация модулей, зависимости

#### 2.2 Реализуй базовую инфраструктуру

Создай общие утилиты:
- Клиент API с аутентификацией
- Вспомогательные функции обработки ошибок
- Форматирование ответов (JSON или Markdown)
- Поддержка пагинации

#### 2.3 Реализуй инструменты

Для каждого инструмента:

**Входная схема:**
- Используй Zod (TypeScript) или Pydantic (Python)
- Добавляй ограничения и понятные описания
- Добавляй примеры в описания полей

**Выходная схема:**
- Где возможно, определяй `outputSchema` для структурированных данных
- Используй `structuredContent` в ответах инструментов (возможность TypeScript SDK)
- Это помогает клиентам понимать и обрабатывать результаты инструментов

**Описание инструмента:**
- Краткое описание функциональности
- Описания параметров
- Схема возвращаемого типа

**Реализация:**
- Async/await для операций ввода-вывода
- Корректная обработка ошибок с понятными сообщениями
- Поддержка пагинации там, где это уместно
- При использовании современных SDK возвращай и текстовое содержимое, и структурированные данные

**Аннотации:**
- `readOnlyHint`: true/false
- `destructiveHint`: true/false
- `idempotentHint`: true/false
- `openWorldHint`: true/false

### Этап 3: Ревью и тестирование

#### 3.1 Качество кода

Проверь:
- Отсутствие дублирующегося кода (принцип DRY)
- Единообразную обработку ошибок
- Полное покрытие типами
- Понятные описания инструментов

#### 3.2 Сборка и тестирование

**TypeScript:**
- Выполни `npm run build`, чтобы проверить компиляцию
- Протестируй с MCP Inspector: `npx @modelcontextprotocol/inspector`

**Python:**
- Проверь синтаксис: `python -m py_compile your_server.py`
- Протестируй с MCP Inspector

Подробные подходы к тестированию и чек-листы качества см. в руководствах для конкретного языка.

### Этап 4: Создание оценочных тестов (эвалов)

После реализации MCP-сервера создай полноценные эвалы, чтобы проверить его эффективность.

**Загрузи [✅ Руководство по эвалам](./reference/evaluation.md) для полных правил оценки.**

#### 4.1 Пойми назначение эвалов

Эвалы нужны, чтобы проверить, могут ли LLM эффективно использовать твой MCP-сервер для ответов на реалистичные и сложные вопросы.

#### 4.2 Создай 10 вопросов для эвала

Чтобы создать эффективные эвалы, следуй процессу из руководства по эвалам:

1. **Изучение инструментов**: перечисли доступные инструменты и пойми их возможности
2. **Изучение контента**: используй ТОЛЬКО операции чтения, чтобы исследовать доступные данные
3. **Генерация вопросов**: составь 10 сложных и реалистичных вопросов
4. **Проверка ответов**: сам реши каждый вопрос, чтобы проверить ответы

#### 4.3 Требования к вопросам эвала

Каждый вопрос должен быть:
- **Независимым**: не зависеть от других вопросов
- **Только для чтения**: требовать только неразрушающих операций
- **Сложным**: требовать нескольких вызовов инструментов и глубокого исследования
- **Реалистичным**: основанным на реальных сценариях, которые важны людям
- **Проверяемым**: иметь один точный ответ, который можно проверить сравнением строк
- **Стабильным**: ответ не должен меняться со временем

#### 4.4 Формат вывода

Создай XML-файл такой структуры:

```xml
<evaluation>
  <qa_pair>
    <question>Find discussions about AI model launches with animal codenames. One model needed a specific safety designation that uses the format ASL-X. What number X was being determined for the model named after a spotted wild cat?</question>
    <answer>3</answer>
  </qa_pair>
<!-- More qa_pairs... -->
</evaluation>
```
